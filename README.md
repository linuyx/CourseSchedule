# 课序 · 浏览器本地课程表

一个使用 React、TypeScript 和 Vite/Vinext 构建的 H5 课程表。页面采用“星期标签 + 当天四节课”的单列布局；即使在大屏幕打开，也会保持居中的 H5 画布。项目不读取外部课程 JSON，也不需要后端或数据库，构建后可直接部署到 nginx。

## 开发与构建

环境要求：Node.js 22.13 或更高版本。

```bash
npm install
npm run dev
```

生产构建：

```bash
npm run build
```

静态站点输出在 `dist/client/`。将该目录中的全部文件复制到 nginx 站点目录即可运行。

## 维护课程数据

页面课程区域提供“维护”入口，可以按课程记录新增、修改和删除。每门课程独立配置课程名、教师、教室、星期、节次和上课周次。

所有课程保存在当前站点域名下的浏览器 `localStorage` 中：

- 存储键为 `course-schedule.local.v1`。
- 首次打开时，系统会将代码内置的初始课程写入浏览器。
- 后续打开时，系统优先使用已经保存的本地课程。
- 已有的版本 1 本地课程数据保持兼容，不需要迁移。

`localStorage` 内部会使用 `JSON.stringify` 和 `JSON.parse` 序列化数据，但项目中不存在需要部署或请求的外部课程 JSON 文件。

维护表单会展示学期内的全部周次，支持直接多选，也提供全选、单周、双周和清空快捷操作。连续或间隔周次会自动压缩保存为 `1-8,11-16` 这样的表达式。

## 初始课程

系统初始课程定义在 `lib/default-schedule.ts`。它包含学期名称、开学日期、总周数和演示课程，并在应用启动时通过与用户课程相同的校验逻辑检查。

修改代码内置课程后，需要重新执行 `npm run build` 并部署新的静态文件。新的内置课程只会提供给首次访问或已经清除该站点本地数据的浏览器；已有用户会继续使用自己维护的数据。

课程字段：

| 字段      | 含义     | 可填写值                       |
| --------- | -------- | ------------------------------ |
| `name`    | 课程名称 | 非空文本                       |
| `teacher` | 教师     | 非空文本                       |
| `room`    | 教室     | 非空文本                       |
| `weekday` | 星期     | `1` 至 `5`，分别代表周一至周五 |
| `period`  | 节次     | 见下方节次表                   |
| `weeks`   | 上课周次 | 单周、区间或逗号组合           |

节次值：

| 值            | 显示名称 |
| ------------- | -------- |
| `morning-1`   | 上午一   |
| `morning-2`   | 上午二   |
| `afternoon-1` | 下午一   |
| `afternoon-2` | 下午二   |

周次写法示例：

- `3`：仅第 3 周
- `1-16`：第 1 至 16 周
- `1-8,10,12-16`：第 1 至 8 周、第 10 周、第 12 至 16 周

开学日期必须是第一教学周的周一。日期、周次、星期或节次不合法时，课程不会被保存，并会显示具体字段错误。

## 本地存储范围

课程只属于“当前浏览器 + 当前网站域名”，不会同步到其他设备、其他浏览器或另一个域名。清除微信/浏览器站点数据、使用无痕模式或卸载应用，都可能导致本地课程丢失。浏览器禁止或无法写入本地存储时，页面会临时展示初始课程并提示无法持久保存。

如果需要多设备共享、多人维护或服务端备份，仍需接入云存储、数据库或后端接口；当前版本不包含这些能力。

## nginx 部署

最简单的站点配置如下：

```nginx
server {
    listen 80;
    server_name example.com;
    root /var/www/course-schedule;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

复制构建结果：

```bash
cp -R dist/client/. /var/www/course-schedule/
```

项目只有一个页面，因此不需要 SPA 回退规则。部署在 nginx 子目录时，静态资源使用相对路径，无需修改代码。
